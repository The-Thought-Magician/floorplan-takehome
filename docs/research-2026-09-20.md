## Blackwell sm_120 stack

- PyTorch Blackwell support from 2.7.0 via cu128 wheels [V] https://pytorch.org/blog/pytorch-2-7/ ; 2.11 dropped cu128 for cu130 [V] https://github.com/pytorch/pytorch/issues/159207
- Local check: torch 2.14.0+cu130, arch list includes sm_120, bf16 matmul and SDPA run on the RTX 5050 Laptop [V, run here]
- flash-attn: no sm_120 wheel, source build fails [V] https://github.com/Dao-AILab/flash-attention/issues/2361 https://github.com/Dao-AILab/flash-attention/issues/2168
- xformers: wheels stop at sm_90 [V] https://github.com/facebookresearch/xformers/issues/1279 ; installing can downgrade torch [V] https://dev.to/madcoolseed/rtx-5090-survival-guide-sm120-cuda-12-and-13-side-by-side-and-the-xformers-trap-25nh
- cuDNN SDPA failures on Blackwell, disable it [V] https://github.com/Comfy-Org/docs/pull/1491
- WSL2 open issues: hidden driver memory https://github.com/microsoft/WSL/issues/40401 , unified memory segfault https://github.com/microsoft/WSL/issues/41483
- vggt-low-vram benchmark on RTX 5070 Laptop 8GB, CUDA 12.8, torch 2.7.1: 25 imgs 3.50GB, 125 imgs 5.83GB, 150 imgs fit [V] https://github.com/harry7557558/vggt-low-vram

## Multi-view models

- VGGT https://github.com/facebookresearch/vggt : 8GB 4070 OOM at 6 imgs (issue 39), 7-8GB for one frame reported (issue 81), May 2026 memory fix [V]
- VGGT-Omega https://github.com/facebookresearch/vggt-omega : A100 25 frames 7.80GB, non-commercial, gated [V]
- FastVGGT https://github.com/mystorm16/FastVGGT , StreamVGGT https://github.com/wzzheng/StreamVGGT (needs FlashAttention-2), VGGT-Long https://github.com/DengKaiCQ/VGGT-Long (metric with MapAnything backbone), VGGT-X https://github.com/Linketic/VGGT-X [V]
- Pi3 / Pi3X https://github.com/yyfz/Pi3 : weights CC BY-NC, no consumer VRAM numbers [V]
- MapAnything https://github.com/facebookresearch/map-anything : metric, Apache checkpoint `map-anything-apache`, latest ckpt Jan 2026, no consumer VRAM numbers [V]
- Depth Anything 3 https://github.com/ByteDance-Seed/Depth-Anything-3 : Small/Base/Metric-L Apache, Giant/Large-1.1 non-commercial, streaming 11.5-28GB peak, 24GB OOM over 100 imgs (issue 40), README installs xformers [V]
- MUSt3R https://github.com/naver/must3r : non-commercial, xformers recommended, no consumer numbers [V]
- AMB3R https://github.com/HengyiWang/amb3r : pins torch 2.5 + flash-attn 2.7.3 [V]
- LingBot-Map https://github.com/Robbyant/lingbot-map : Apache, relative scale, OOM at 16GB reported (issue 6) [V]
- VGG-T3 https://arxiv.org/abs/2602.23361 , GGPT https://arxiv.org/abs/2603.11174 : code not verified
- No MapAnything v2 or Depth Anything 4 as of today [V, searched]

## WebXR on Android Chrome

- Raw camera access shipped by default Chrome 107 Android [V] https://chromestatus.com/feature/5759984304390144 ; spec https://immersive-web.github.io/raw-camera-access/ ; readback sample https://chromium.googlesource.com/chromium/src/+/main/third_party/webxr_test_pages/webxr-samples/proposals/camera-access-barebones.html
- getCameraImage crash with XRProjectionLayer before Chrome 149 [V] https://github.com/mrdoob/three.js/issues/33404
- getUserMedia may fail with NotReadable during immersive-ar [V, spec issue] https://github.com/immersive-web/webxr-ar-module/issues/87
- XR framebuffer is opaque, captureStream on the XR canvas records nothing [V] https://raw.githubusercontent.com/immersive-web/webxr/main/index.bs ; large-canvas MediaRecorder bug on Android https://paul.kinlan.me/chrome-bug-897727mediarecorder-using-canvas-capturestreamfails-for-large-canvas-elements-on-android/
- MediaRecorder mp4 on Android from Chrome 126 [V] https://chromestatus.com/feature/5163469011943424
- Depth sensing spec https://immersive-web.github.io/depth-sensing/ ; depthTypeRequest, matchDepthView, pause/resume shipped Chrome 139 Android [V] https://chromestatus.com/feature/5074096916004864
- ARCore-backed Chrome: cpu-optimized only, luminance-alpha or unsigned-short only, smooth only, no confidence, ~160x90, rejects buffers over 43,200 px [V] https://chromium.googlesource.com/chromium/src/+/main/device/vr/android/arcore/arcore_impl.cc
- Depth resolution per device config, ToF phones larger [V] https://github.com/google-ar/arcore-android-sdk/issues/1314
- ARCore accuracy guidance: best 0.5-5m, white walls imprecise [V] https://developers.google.com/ar/develop/depth ; raw depth with confidence is native only https://developers.google.com/ar/develop/java/depth/raw-depth ; independent indoor test https://arxiv.org/abs/2204.01693 (exact MAE not extracted)
- iOS: no WebXR immersive-ar in Safari [V] https://developer.apple.com/forums/thread/756850 , https://webkit.org/blog/18178/webkit-features-for-safari-26-6/
- Depth intrinsics: XRDepthInformation includes XRViewGeometry, equals the view when matchDepthView is true [V, spec]
- Phone model: navigator.userAgentData.getHighEntropyValues(['model']) [V] https://privacysandbox.google.com/blog/user-agent-reduction-android-model-and-version
